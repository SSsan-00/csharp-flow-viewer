# csharp-flow-viewer

Windows で、C# メソッドの制御フローと Razor ページのイベントを解析して Mermaid で表示する開発ツールです。左でプロジェクトのファイルと解析対象を選び、中央でフローをたどり、右で対応するソースを確認できます。`.cshtml` を選ぶとページの概要を表示し、画面イベント・JavaScript 関数・送信先の PageModel を確認できます。`.cs` / `.cshtml.cs` は Roslyn による既存の C# 解析を使用します。

**このアプリは指定どおり .NET 9.0 を使用します。.NET 9 の Microsoft サポートは 2026 年 11 月 10 日に終了しました。** 同梱ランタイムも同じライフサイクルです。 [Microsoft .NET サポートポリシー](https://dotnet.microsoft.com/platform/support/policy/dotnet-core)

## 利用環境

| 用途 | 必要なもの |
| --- | --- |
| 発行済み EXE の実行 | Windows 10 バージョン 1809 以降の x64。アプリ用の .NET 9、Windows Desktop Runtime、WebView2 が読み込む Windows SDK の .NET ライブラリは EXE に同梱 |
| プロジェクトの解析 | `dotnet` が PATH にあり、対象プロジェクトを理解できる .NET SDK 8 以降、必要なターゲティングパックおよび復元済みの参照が利用できること。検証に使用した SDK は 9.0.321 |
| フロー図のプレビュー | Microsoft Edge WebView2 Evergreen Runtime x64。利用できない場合はノード一覧、ソース連動、Mermaid 出力を利用可能 |
| このリポジトリをビルド | .NET 9 SDK 9.0.300 以降の 9.0 系。Node.js 22.12 以降は Mermaid バンドルを再生成する場合とブラウザテストで使用 |

SDK の選択はプロジェクトのディレクトリを起点とする `global.json` とインストール済み SDK に依存します。異なる環境では MSBuild の評価や参照の解決結果も変わります。SDK スタイルのプロジェクトで検証しています。解析には Roslyn 4.14（C# 13）を使用します。Visual Studio 固有の設計時ターゲット、ワークロードや独自 NuGet SDK を使うプロジェクトは読み込みに失敗する場合があります。 [WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/#download-section)

## 使い方

アプリは同じ Windows セッションで一つだけ起動します。再度起動すると、開いているウィンドウを表示します。

1. **プロジェクトを開く…**（Ctrl+O）で信頼できる `.csproj` を選びます。上部に評価に使った SDK と、構成・対象フレームワークを表示します。候補が複数ある場合は切り替えられます。ソースやプロジェクトの変更は **再読み込み** で反映します。
2. 左の一覧で `.cs`、`.cshtml.cs`、または `RZ` バッジの付いた `.cshtml` を選択します。`.cshtml` は選択するとページの概要が開き、下の一覧からイベントや JavaScript 関数を選べます。C# ファイルでは従来どおりメソッドを選びます。ファイル検索欄ではファイル名やプロジェクトからの相対パスで、解析対象の検索欄では名前や行番号で絞り込めます。C# のオーバーロードは型・引数・行番号で区別できます。
3. 中央の図はホイール、拡大・縮小ボタン、ドラッグ、右端の縦スクロールバーで操作します。**検索** または図にフォーカスして Ctrl+F を押すと、ノードを検索できます。**全体** でフィットします。ペイン間の仕切りはドラッグで調節できます。図のノードと右のソースをクリックして相互に移動できます。別メソッドのソースをクリックすると、そのメソッドの図に切り替わります。エディタでは Ctrl+F で検索、Ctrl+G で行移動ができます。長い行は表示幅に合わせて折り返します。
4. C# の呼び出しは同じファイル内の実装を一意に特定できた場合、Razor の送信先は対応する PageModel ハンドラーを特定できた場合に、**呼び出し先へ** から別図に移動できます。Razor から PageModel へはファイルをまたいで移動します。**戻る**（Alt+←）で呼び出し元のファイル・ノードに戻れます。それ以外の別ファイルの C# メソッドを確認するには対象ファイルを左で選択します。
5. **コピー** と **.mmd 保存** で Mermaid テキストを取得できます。下部の **診断** で解析や描画の詳細を確認できます。右上のテーマボタンでライト／ダークを切り替えます。

アプリを再起動すると、前回のプロジェクト、構成、対象ファイルを開きます。同じファイルを開き直すと、最後に選んだメソッド、ソース位置、図の位置と倍率、ノードの選択と注釈が復元されます。表示状態はプロジェクト、ファイル、構成、対象フレームワークごとに保存します。ソースや追跡設定が変わって図が一致しなくなった場合は、メソッドとソース位置を復元します。

架空のサンプルは `samples/OrderProcessing/OrderProcessing.csproj` です。必要に応じて `dotnet restore samples/OrderProcessing/OrderProcessing.csproj` を実行し、`Pages/Order.cshtml.cs` の `OnPost` と `Submit` を開いてください。サンプルを起動する必要はありません。

## Razor ページの解析

同じファイル一覧で `Pages/Order.cshtml` を選択すると、`@:` と `<text>` に囲まれたボタンやインラインの JavaScript イベントを含む概要が開きます。ファイル一覧は選択した構成・対象フレームワークで評価した MSBuild の `Content`、`None`、`AdditionalFiles`、`RazorGenerate` 項目も使用し、除外したファイルをディレクトリ走査で復活させません。

ページ全体はイベントと送信先の **静的な候補の関係図** です。`@if` 等はサーバーでの描画条件として表示し、表示後のブラウザーで実行する JavaScript の分岐と区別します。各ノードは元の `.cshtml` の位置に対応します。インライン `<script>` の初期化や関数を選ぶと、その範囲に含まれる Razor の `@if` や `@for` なども「Razor · JavaScriptの生成」として別枠で表示します。特定できたハンドラーの **呼び出し先へ** は別ファイルの PageModel に移動し、**戻る** で元のイベント・ノードへ復帰します。

| 対象 | 表示する情報 |
| --- | --- |
| Razor / HTML | `@:`、`<text>`、描画条件、フォーム、送信ボタン、リンク、`onclick`・`onchange` 等の `on*` 属性 |
| JavaScript | Acornima による構文解析、関数、呼び出し、if、短絡評価、基本的なループ、switch、return |
| イベント登録 | `addEventListener`、`element.onchange = ...`、jQuery の `.on()` / `.bind()` / `.delegate()` / `.live()`、対応する `.change()` / `.click()` 等の省略形 |
| 旧式の記述 | `window.event`、`srcElement` 等を通常の JS 式として読み、`attachEvent` は旧APIの登録候補として表示 |
| XMLHttpRequest | `open()` のメソッド・URLと `send()` の本文式、非同期／同期指定、応答イベントの候補。応答関数は送信直後に同期実行する処理として展開しない |
| PageModel | `@model`、継承した `_ViewImports.cshtml`、公開ハンドラーを確認し、解決できた現在ページへの送信から C# 詳細図へ移動 |

Razor の解析にはビルド時の .NET 9 SDK が持つ公開の中間表現 API を使用し、必要なコンパイラー DLL をアプリとともに配布します。Razor の非公開構文木へリフレクションでアクセスせず、対象ページや JavaScript を実行しません。`asp-*` の送信先解釈には既知の組み込み Tag Helper の有効化・除外を反映します。

### 解析範囲と未解決の表示

- ページの概要は候補の索引です。ブラウザーの実行履歴ではありません。イベントの取消、複数の登録、動的な DOM、実行順によって実際の動作は変わります。
- 描画フローは Razor に現れる代表的な制御構文の静的な概要です。条件式の実行、C# のすべての文や例外経路、`try / catch` や `goto case` の厳密な解析は行いません。
- `<script>` 内で Razor が JavaScript を条件付きで生成する場合は、各生成経路と元ソースを確認できます。ブラウザー側の図では生成部分を解析境界として示し、排他的な分岐を連続実行とみなしません。生成部分を除くと JS の構文が成立しないときも、初期化項目で Razor の生成フローと診断を確認できます。生成された JS の動作や動的な送信先は確定しません。
- 外部 `.js`、レイアウト、部分ビューの展開はこのページ単独の解析範囲外です。外部スクリプト参照は診断に表示します。別のページ・動的な URL・動的セレクターを根拠なく現在の PageModel や一つの要素へ結び付けません。
- `act` 等の送信値と C# の `switch` の間の値追跡、任意の Ajax ライブラリーの意味解析、`eval` の実行結果、JS の例外伝播の完全な解析は行いません。対応するソースと未解決の理由を確認してください。
- JavaScript の `try/catch/finally` 等、詳細なフローを展開しない構文は境界として表示します。未知の処理を空の成功経路にはしません。
- 概要は先頭 200 件のイベントと上限付きの通信候補、JS 詳細は上限付きのノード数を表示します。省略がある場合は診断に記載します。
- グレーアウトは表示中の候補グラフの接続に対する注釈です。Razor 概要に付けた注釈から、実行時の DOM や通信の到達不能を判定しません。

## ノードの注釈

図のノードを右クリックすると、マーク、グレーアウト、解除を選べます。マークは選択したノードだけに適用します。グレーアウトは選んだノードと、そのノードを通る場合にだけ到達する後続ノードに適用します。別経路からも到達する合流点は通常どおり表示します。`switch` の `case` をグレーアウトすると、その `case` に一致した側だけをたどります。次の `case` と、ほかの `case` からも通る処理は通常どおり表示します。ソースの対応箇所にも注釈を反映します。

図の下の **注釈…** から、現在の図のマークとグレーアウトをそれぞれ一括クリアできます。実行前に確認画面が表示されます。同じメニューから、現在の図の注釈を JSON に書き出したり読み込んだりできます。読み込み先では同じファイルのメソッドを開き、ソースや追跡設定をそろえてください。

## 追跡対象外の設定

上部の **追跡設定…** で、`Math.Abs` や `LogDebug` のような名前をそのまま指定できます。`Math.*` のように `*` などの記号を含む入力は正規表現として扱います。名前の区切りに使う `.` だけでは正規表現になりません。メソッド名、型名付きの名前、名前空間を含む名前のいずれかに大文字と小文字を区別して全体一致した呼び出しが対象です。引数の評価と分岐は図に残ります。

設定は保存時に現在の図へ反映され、次回起動時にも適用されます。チームで共有するには **JSON を書き出す…** を使い、受け取った側で **JSON を読み込む…** から開いて保存します。

## 図の読み方と解析範囲

- `SemanticModel` と `ControlFlowGraph` を用います。条件辺の True／False は CFG の `ConditionKind` と遷移種別から求めます。短絡評価、三項演算子、switch、ループの戻り先を保持します。switch の対象式、case の判定、when の条件を表示します。
- 単純な代入と代入値は図に表示されません。代入内の通常のメソッド呼び出しは実行順で表示します。演算子の内部名（`op_XXX`）は省き、オペランドの評価に含まれる呼び出しを表示します。プロパティとインデクサーの getter／setter はメソッド一覧とフロー図から省きます。正確な引数や値は右のソースで確認してください。`break`、`continue`、値のない `return`、再スローは Roslyn CFG が通常辺にまとめることがあるため、一時的な解析専用コンパイルで位置を追跡します。
- 呼び出しノードに別メソッドの本体は展開されません。外部ファイル、デリゲート、動的呼び出し、実装を特定できない仮想呼び出しには同一ファイル内の移動リンクが付きません。再帰と循環は明示的な移動でたどれます。
- using と await using が暗黙に生成する後始末の finally、null 判定、Dispose／DisposeAsync は図から省きます。初期化式の呼び出しと、明示的な finally・Dispose 呼び出しは表示します。省いた後始末の実行順と例外は図に表示されません。
- 通常遷移と return では CFG が示す順に明示的な finally を経由します。同じ finally が別の継続先を持つ場合は図で複数回表示されます。明示した例外型とフィルターなしのハンドラーを特定できる場合は、必要な finally から catch に接続します。実行時型・例外フィルター・暗黙の例外が関係する場合は、例外探索や巻き戻しを境界として表示します。独立した catch、filter、finally の入口は実行時に到達し得る領域です。全ての例外の発生位置やハンドラー選択、その後の実行を予測する機能はありません。
- 破線は Roslyn または定数条件で判断した到達不能な経路です。コンパイル条件で除外されたコードはソースに残り、図の対象外です。抽象メソッドなど実装がない選択肢、未解決の式、参照不足、複合パターン内部など個別表示ができない場合は、診断で影響を表示します。
- C# 解析はメソッド、コンストラクター、演算子、イベントアクセサーと、対応するメソッド内のローカル関数を対象にします。C# のトップレベルの本体、ラムダや匿名関数の別図、自動実装アクセサーの本体、コンパイラーが生成する async・iterator の状態機械は対象外です。分解代入や暗黙のインデクサーは一部表示されます。Razor／HTML／JavaScript の範囲は「Razor ページの解析」を参照してください。
- 650 ノード、1,000 遷移、Mermaid 380,000 文字のいずれかを超える図は、プレビューで軽量な SVG レイアウトを使用します。全体の `.mmd` は出力でき、外部レンダラーではそちらの上限設定も必要です。解析中に finally の継続先が 4,096 に達した場合は部分解析になります。

## ソースと通信

**信頼できるプロジェクトだけを開いてください。** 読み込みでは MSBuild によるプロパティ評価と設計時ビルドが行われます。プロジェクト、インポート先や SDK のカスタムターゲット・タスクは、そのプロセスの権限で動く可能性があります。アプリはソースのビルド成果物を起動せず、Roslyn に渡すプロジェクトからアナライザー／ソースジェネレーターを外します。その生成物が参照解決に必要な場合は部分解析になります。

アプリは対象の NuGet restore を開始せず、NuGet SDK リゾルバー、Workload リゾルバーと .NET CLI テレメトリを無効にします。カスタム MSBuild タスクや OS をネットワークから隔離する機能はありません。接続を禁止する業務環境では OS の通信制限下で使用してください。

Mermaid のライブラリとページを EXE に同梱します。WebView2 のアプリページはメモリから配信し、そのページの外部リクエスト・ナビゲーションをブロックします。ソースと Mermaid の内容を外部サービスに送信しません。アプリは解析ログやソースを保存しません。テーマ、追跡設定、前回のプロジェクトとファイルの表示状態は `%LOCALAPPDATA%\csharp-flow-viewer` に保存します。コピーと保存は利用者の操作でソース由来のラベルをクリップボードや指定ファイルに書き出すため、共有前に内容を確認してください。WebView2 は一時プロファイルを使い、終了時に削除を試みます。

## ビルド・発行

```powershell
dotnet build csharp-flow-viewer.sln -c Release
dotnet test tests/Flow.Tests -c Release
dotnet publish src/Flow.Desktop -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:DebugType=None -p:DebugSymbols=false -o artifacts/win-x64
```

`artifacts/win-x64/csharp-flow-viewer.exe` が配布対象です。WPF を選んだ理由はネイティブの Windows ウィンドウ、サイズ調整可能なペイン、ソースエディターを利用でき、Windows Desktop Runtime を単一ファイルに同梱できるためです。WPF と Roslyn の別プロセス用資産を展開するため `IncludeAllContentForSelfExtract` を有効にしています。実行先のユーザーにはバンドル展開用の一時ディレクトリへの書き込み権限が必要です。Windows 上では署名されていない実行ファイルに対する OS の警告が出る場合があります。

責務は `Flow.Analysis`（MSBuild／Roslyn）、`Flow.Model`（図と対応ソース範囲）、`Flow.Mermaid`（安定した ID とエスケープを持つ出力）、`Flow.Desktop`（WPF、AvalonEdit、ローカルプレビュー）に分かれています。

Mermaid を更新する場合は、`npm --prefix tools/preview ci` と `npm --prefix tools/preview run build` で同梱 JS とライセンス一覧を再生成します。ブラウザテストは `CFV_MERMAID_FIXTURE` に生成先の絶対パスを指定して `dotnet test tests/Flow.Tests` を実行し、`CFV_CHROMIUM` に Chromium の実行ファイルを指定して `npm --prefix tools/preview test` を実行します。
